# قياس وتمركز Dynamic Island على Windows

## قاعدة الإحداثيات

تُقاس مواضع الجزيرة ومستطيلات الشاشة بالبكسل الفيزيائي. عند الإقلاع وبعد كل انتقال مستقر ترسل صفحة الجزيرة مستطيل الكبسولة المرئي وارتفاع مرحلة الخمول. يقرأ Rust مستطيل النافذة ومساحة عميل WebView والشاشة الأقرب عبر `MonitorFromWindow` و`GetMonitorInfoW`، ويسجل `rcMonitor` و`rcWork` ومقياس Tauri وDPI الخاص بالنافذة.

تبقى الأبعاد المرئية كما هي: مرحلة الخمول 38 CSS px، وكبسولة الخمول 44×24 CSS px بنصف قطر 12px، والموسيقى 112×24 CSS px بنصف قطر 9px؛ موضع أعلى جسم الخمول 7px ومركزه عند 19px. تضيف حاوية WebView هامشًا شفافًا غير مرئي مقداره 1 CSS px حول الرسم، لذلك تكون نافذة الإقلاع 46×40 بدلًا من تغيير شكل الكبسولة أو تصغيرها. يسترد JavaScript مساحة الرسم بطرح الهامش، وتضيف دالة موحدة الهامش إلى كل قياس يرسله إلى Windows.

تتغير ارتفاعات الحالة الموسعة مع معامل الملاءمة وإزاحة الارتكاز؛ لذلك يقبل Rust مجالًا محدودًا من المقاسات التي تنتجها الواجهة بدل قائمة ارتفاعات ثابتة. يشمل الارتفاع هامش بكسل للحساب وهامش النافذة، وتُسجّل رسالة الخطأ المقاس الفعلي إذا خرج عن الحدود. يعود وضع التلاوة الكاملة إلى 384×210 CSS px، وبطاقة الصلاة 400×170، والموسيقى المستطيلة ذات الزوايا الهادئة. تظل مرساة الخمول ثابتة خلال النابض، ويُصحح `SetWindowPos` والقياس اللاحق الإحداثيات ضمن سماحية نصف بكسل فيزيائي.

نافذة الجزيرة نافذة شفافة مستقلة فقط؛ لا تُنشأ نافذة نظامية إضافية ولا تتغير مساحة العمل أو مواضع نوافذ التطبيقات الأخرى. في `idle` و`compact` توسّع منطقة Windows الأصلية بكسلًا فيزيائيًا واحدًا حول مستطيل الرسم المستدير، كي لا تمر حافة القص عبر بكسلات التنعيم الجزئية. تبقى النقاط البعيدة عن شكل الجزيرة خارج منطقة النافذة وتصل نقراتها إلى التطبيقات التي تحتها؛ عند التوسيع تزال المنطقة ويعود مستطيل النافذة الكامل.

## سجل التشخيص

تُكتب القياسات بصيغة JSON Lines إلى `app_config_dir()/island-geometry.jsonl`. يحتفظ السجل بإحداثيات `rcMonitor` و`rcWork`، ومركز الارتكاز المحسوب من أصل الشاشة، ومركز الكبسولة قبل التصحيح وبعده، وعدد محاولات التصحيح. يدوّر السجل بعد تجاوزه 4 MiB. ينسخ خيار صينية النظام السجل إلى مجلد التنزيلات ليمكن إرفاقه عند ظهور اختلاف على جهاز المستخدم.

## تحقق Windows

يشغّل CI النسخة التنفيذية الناتجة على Windows، ويتحقق من بقاء كبسولة الخمول المرئية 44×24 CSS px ووجود هامش شفاف لا يقل عن بكسل فيزيائي حولها. يفعّل الاختبار منفذ CDP محليًا مؤقتًا عبر متغير العملية وقيمة WebView2 خاصة باسم ملف التطبيق على عامل GitHub المؤقت؛ يحفظ القيمة السابقة ويعيدها ويحذف المفاتيح الجديدة بعد الإنهاء. لا يتغير إعداد Windows على جهاز المستخدم ولا تُضاف واجهة اختبار إلى التطبيق. يرسل الاختبار حالة مشغل اختبارية عبر المنفذ المؤقت، ثم ينقر فعليًا على كبسولة الموسيقى 112×24 لفتح الوضع الكامل 384×210. يتحقق من أن الرسم الكامل داخل مساحة WebView مع خلوص مقاس أسفل المحتوى، وأن موضعه العلوي ثابت خلال الحركة. يختبر كذلك النقر المار خارج مستطيل الموسيقى وعند زاويته المستديرة، ثم يختبر بطاقة الصلاة الموسعة والخمول من جديد. تُرفع صور كل حالة وسجل JSONL وملخص النتائج كـartifact. غياب سطح عرض تفاعلي أو تعذر أي خطوة يجعل الاختبار يفشل؛ لا يُعامل التخطي على أنه نجاح.

## مراجع Microsoft

- [SetWindowRgn](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowrgn): يحدد منطقة الرسم الفعلية للنافذة وإحداثياتها.
- [Window Features: Layered Windows](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features): يشرح hit-testing والشفافية في النوافذ ذات الطبقات.
- [Apply Rounded Corners](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/apply-rounded-corners): يوضح تفاعل الزوايا الأصلية مع alpha والـwindow regions.
- [MonitorFromWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-monitorfromwindow)
- [GetMonitorInfoW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmonitorinfow)
- [GetDpiForWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getdpiforwindow)
- [Use Visual Studio Code to debug WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/how-to/debug-visual-studio-code): يشرح تعيين `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` لتشغيل منفذ CDP، وهو مفعّل مؤقتًا في عملية الاختبار فقط.
